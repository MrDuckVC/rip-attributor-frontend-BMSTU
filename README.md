# Атрибутор — фронтенд ЛР5

Гостевое SPA для каталога корпусов текстов потенциальных авторов. Тема — атрибуция анонимного текста по частотности служебных слов. Услуга в коде: **Corpus**, коллекция: **corpora**. Показатели — количество слов `word_count` и процент предлогов `prep_percent`; фильтрация по минимальному количеству слов.

**React + TypeScript + Vite + React-Bootstrap.** Только локальные mock-данные и медиа. Бэкенд, PostgreSQL, MinIO/S3 и интернет для работы запущенного приложения не требуются. Расчёт атрибуции и заявки не реализуются.

В соответствии с уточнением преподавателя от **26.10.2026** реализованы **две страницы** и четыре пункта меню, из которых два доступны. Устаревшее требование о трёх страницах и подключении API к ЛР5 не применяется. Redux, React Context и `Outlet context` в пользовательском коде отсутствуют.

## Запуск

Требуется Node.js **22.12+** (рекомендуется Node.js 24) и npm. Установка зависимостей требует доступа к npm registry, последующая работа приложения — только локальных ресурсов.

Проверьте `node --version` именно в терминале, из которого запускаете проект: IDE и обычный Bash могут использовать разные версии. Системный Node.js 18 не поддерживается и вызывает ошибку `crypto.hash is not a function`.

Для переключения через [nvm](https://github.com/nvm-sh/nvm) в проект добавлен `.nvmrc` с Node.js 24. Если nvm ещё не установлен, установите его по [официальной инструкции Node.js](https://nodejs.org/en/download), затем откройте новый терминал. В каталоге проекта выполните:

```bash
nvm install
nvm use
node --version  # v24.x.x
npm ci
npm run dev
```

Если Node.js 24 уже выбран другим способом, достаточно `npm ci` и `npm run dev`. После переключения Node.js переустановите зависимости через `npm ci`. Вариант запуска через Docker ниже не зависит от версии Node.js на хосте.

Открыть **http://localhost:3000/corpora**. Порт фиксирован: если 3000 занят, остановить другой процесс. Корень `/` перенаправляет на плитку.

Сборка и локальный просмотр:

```bash
npm run build
npm run preview
```

Приложение доступно на том же порту 3000. Dev-сервер и preview одновременно не запускать. При размещении `dist/` на другом сервере настроить возврат `index.html` для SPA-маршрутов `/corpora` и `/corpora/:id`.

### Docker

```bash
docker compose up --build
```

Открыть http://localhost:3000/corpora. Исходники подключены volume; Vite использует polling для hot reload. Зависимости находятся в отдельном volume. Остановить: `docker compose down`. При изменении зависимостей удалить только volume этого проекта через `docker compose down -v`, затем пересобрать. На Linux работающий контейнер для защиты показать в Portainer; на Windows/macOS — в Docker Desktop.

## Страницы, поля и кнопки

### Краткое описание для защиты

| Страница | Поля и данные | Кнопки и действия |
|---|---|---|
| Плитка `/corpora` | Минимальное количество слов; изображения, названия, объём и лайки корпусов | Поиск, переход из карточки в ленту, «Назад»/«Далее». Корзина отключена. |
| Лента `/corpora/:id` | Видео, название, описание, количество слов, процент предлогов и лайки | «ещё»/«свернуть», следующий корпус. Лайк отключён. |

Нижнее меню: **Лента** и **Плитка** доступны; **Добавить** и **Вход** отключены. Данные — локальная mock-коллекция, запросов к backend и S3 нет.

### Плитка — `/corpora`

| Элемент | Поведение |
|---|---|
| «Объём текста (кол-во слов)» | Ползунок 0–200 000, шаг 5000. Подпись `≥` показывает выбранный порог. |
| Синяя кнопка с лупой | Применяет фильтр `word_count >= minimum`. Само перемещение ползунка список не меняет. |
| Карточка | Портрет, название, количество слов и счётчик лайков из mock. Нажатие открывает этот корпус в ленте. |
| Корзина | Сохранена из исходного дизайна, отключена для гостя. |
| «Назад» / «Далее» | Пагинация по 6 корпусов; текущая страница указана между кнопками. |
| «Корпусы не найдены» | Пустой результат фильтра; остальные записи автоматически не подставляются. |

Применённый порог и страница записываются в URL: `/corpora?query=50000&page=1`. Новый фильтр сбрасывает страницу на первую. Обновление страницы сохраняет параметры. Некорректные параметры безопасно нормализуются: неверный/отрицательный порог → 0, порог больше максимума → 200000, неверная страница → 1, страница за пределами списка → последняя доступная.

### Лента — `/corpora/:id`

| Элемент | Поведение |
|---|---|
| Вертикальное видео | Локальный ролик с автоматическим воспроизведением без звука, `loop`, `muted`, `playsInline`. |
| Название и описание | Поверх видео в исходном стеклянном блоке. «ещё» разворачивает описание, «свернуть» возвращает краткий вид. |
| Сердце и число | Количество лайков из mock. Изменять лайк гостю нельзя. |
| СЛОВ | `word_count` выбранного корпуса. |
| ПРЕД | `prep_percent`, процент предлогов; для отсутствующего значения — прочерк. |
| Стрелка вниз | Следующий корпус по порядку полного mock-массива; после последнего — первый, как в backend. |

Идентификаторы произвольные: после `/corpora/1` идёт `/corpora/3`, не `id + 1`. Корпус открывается также по прямой ссылке и после F5. Неизвестный ID показывает «Корпус не найден» со ссылкой «К плитке».

### Общая навигация

Панель расположена внизу оболочки на всех страницах:

| Пункт | Действие |
|---|---|
| Лента | Открывает первый mock-корпус. |
| Добавить | Отключён в ЛР5. |
| Плитка | Открывает каталог; после перехода из карточки сохраняет применённый фильтр и страницу. |
| Вход | Отключён в ЛР5. |

Активный пункт подсвечивается синим. Логотип «Атрибутор» ведёт на плитку. Переходы используют React Router без перезагрузки документа.

## Дизайн и локальные данные

Сохранён дизайн ЛР1: **412×917**, JetBrains Mono, синий `#316DE0`, фон `#F4F7FA`, полупрозрачные белые карточки и панели, округлые кнопки. CSS перенесён из `resources/style.css` backend; шаблоны для сверки предоставлены пользователем. Адаптивных перестроений и медиазапросов нет: размеры не меняются, оболочка центрируется. Маленькое окно прокручивается целиком.

Изменения, необходимые для ЛР5: четвёртый пункт меню с уменьшенными отступами, отключённые гостевые действия и обозначение **ПРЕД** вместо устаревшего **МЕСТ**. Bootstrap подключён до собственных стилей, чтобы его стандартный вид не менял макет.

- `src/modules/types.ts` — публичный тип корпуса, совместимый с полями DTO backend ЛР4.
- `src/modules/mock.ts` — 8 демонстрационных корпусов одного потенциального автора с разными подборками. Числовые показатели условные, анализ текста не выполняется.
- `src/modules/corpora.ts` — чистые функции фильтрации, пагинации и переходов по mock-коллекции.
- `src/components/` — карточка, фильтр, медиа и нижняя навигация с типизированными props.
- `src/pages/` — две страницы. `src/App.tsx` задаёт маршруты и оболочку.
- `public/media/puskin.png`, `public/media/puskin.mp4` — исходные медиа backend, включённые в отдельный фронтенд-проект. Видео **720×1280**.
- `public/fonts/` — локальные JetBrains Mono 500/700 (латиница и кириллица), лицензия `OFL.txt`. Обращений к Google Fonts нет.

При пустом `image_url` компонент `CorpusImage` подставляет `DEFAULT_IMAGE`; при пустом `video_url` компонент `CorpusVideo` подставляет `DEFAULT_VIDEO`. Константы находятся в `src/modules/media.ts`. Ошибка загрузки пользовательского медиа также включает заглушку. Если недоступно дефолтное видео, показывается изображение. Первая mock-запись имеет оба URL пустыми для демонстрации.

Состояние фильтра передаётся компоненту через props (`value`, `onChange`, `onSubmit`). Применённые параметры хранятся в URL. Адрес возврата из ленты передаётся через router navigation state и props, без собственного контекста. Данные mock импортируются напрямую; `fetch`, Axios и API-fallback отсутствуют. В Network отображаются локальные статические ресурсы; в dev-режиме также модули Vite и HMR.

## Проверки

```bash
npm run lint
npm test
npm run build
```

Браузерные проверки Chromium (первичная установка браузера требует интернета):

```bash
npx playwright install chromium
npm run test:e2e
```

На Linux для первого запуска Chromium также нужны его системные библиотеки. Если Playwright сообщает об отсутствующей библиотеке, установить зависимости командой `npx playwright install-deps chromium` (требует прав администратора).

Playwright сам запускает Vite на порту 3000, если он свободен. Для проверки production-сборки отдельно запустить `npm run preview`, затем `npm run test:e2e`: тесты используют уже работающий сервер. Проверяются граница фильтра, пустой результат, пагинация, URL/F5, лента, локальное видео, фиксированные размеры и отсутствие API/внешних запросов.

Проверено при реализации: **13** тестов Vitest, TypeScript/production-сборка и ESLint; **3** браузерных сценария на Vite, через Docker Compose и на production-сборке. Дополнительно проверены цвета неактивного лайка и размер фонового изображения при отказе видео. Это проверка приложения; документ со скриншотами и работы по РПЗ остаются за пользователем.

## Контрольные вопросы

| Вопрос | Краткий ответ и пример в проекте |
|---|---|
| React | Библиотека декларативного построения интерфейсов из компонентов. Описываем состояние интерфейса, React обновляет DOM при изменениях. |
| Компонент и элемент | Компонент — функция, описывающая часть интерфейса, например `CorpusCard`. Элемент — результат JSX, описание конкретного узла/компонента, например `<CorpusCard corpus={corpus} catalogSearch="" />`. |
| Props и состояние | Props — входные данные только для чтения. State — локальные изменяемые данные. `CorpusFilter` получает props от `GridPage`, где живёт `value` в state. |
| `useState` | Возвращает текущее значение и setter. Setter запрашивает новый рендер; нельзя изменять состояние напрямую. Применён для ползунка, раскрытия описания и ошибок видео. |
| `useEffect` | Синхронизирует компонент с внешней системой после фиксации рендера. В `App` обновляет `document.title` при изменении `isFeed`. Cleanup нужен для созданных подписок/таймеров; здесь они не создаются. |
| Жизненный цикл | Монтирование, обновление и размонтирование. Эффект выполняет setup и при необходимости cleanup перед повторным setup и при размонтировании. В StrictMode во время разработки React дополнительно проверяет эффекты циклом setup/cleanup/setup. |
| Хуки маршрутизации | `useLocation` — текущий адрес/state, `useParams` — ID из маршрута, `useSearchParams` — query/page. Хуки вызываются на верхнем уровне компонента, вне условий и циклов. |
| Vite | Инструмент разработки и сборки: локальный сервер, HMR, обработка модулей и production-сборка. Проверку типов отдельно выполняет `tsc` в `npm run build`. |
| Babel | Инструмент преобразования синтаксиса JavaScript/JSX. В используемом `@vitejs/plugin-react` задействован для React Fast Refresh в разработке; это не проверка типов TypeScript. JSX/TSX преобразуется в вызовы React JSX runtime. |
