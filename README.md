# Атрибутор — фронтенд ЛР6

SPA каталога корпусов текстов потенциальных авторов. Тема — атрибуция анонимного текста по частотности служебных слов. Услуга в коде — **Corpus**, коллекция — **corpora**. Тематические поля: `word_count` (количество слов) и `prep_percent` (процент предлогов). Фильтр — минимальное количество слов.

**React + TypeScript + React-Bootstrap + Redux Toolkit + Axios + Vite.** Контракт и API соответствуют соседнему Go-проекту `rip-attributor-backend`, ЛР4. Сохранены макет **412×917**, JetBrains Mono, цвет `#316DE0`, светлый фон и нижнее меню. Адаптивность, PWA и расчёт атрибуции в ЛР6 не входят.

## Запуск

Node.js **22.12+**; `.nvmrc` выбирает Node.js 24.

```bash
nvm use
npm ci
npm run dev
```

Открыть **http://localhost:3000/corpora**. Порт фиксирован. Для гостевой демонстрации достаточно фронтенда: если API недоступен, плитка и лента после попытки AJAX загружают локальные mock-данные. Логин, создание, публикация, удаление и лайки требуют настоящего бэкенда.

Для полного сценария запустить Go API, PostgreSQL, Redis и MinIO согласно README бэкенда. По умолчанию API слушает `localhost:8080`, MinIO API — `localhost:9000` (9001 — консоль, не S3). Пользователя зарегистрировать через Swagger/Postman, затем войти через страницу `/login`; формы регистрации во фронтенде нет. Не требуется изменять CORS бэкенда.

Настройки можно скопировать из `.env.example` в `.env`:

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `API_PROXY_TARGET` | `http://localhost:8080` | Адрес API для сервера Vite |
| `S3_PROXY_TARGET` | `http://localhost:9000` | Адрес MinIO для сервера Vite |
| `VITE_MINIO_PUBLIC_URL` | `http://localhost:9000` | Точный origin подписанных URL из бэкенда |

После изменения окружения перезапустить Vite; для preview пересобрать приложение. Секреты MinIO/PostgreSQL/JWT на фронтенд не передаются. `/api` сохраняет префикс при проксировании; `/s3` удаляет только этот префикс. Для подписанных URL сохраняются путь и query, восстанавливается подписанный Host. Заголовки Authorization/Cookie из медиа-запроса в S3 не передаются.

```bash
npm run build
npm run preview
```

Dev и preview одновременно не запускать. Оба поддерживают API/S3 proxy. При размещении `dist/` на другом сервере нужны собственные reverse proxy `/api`, `/s3` и возврат `index.html` для SPA-маршрутов.

### Docker

```bash
docker compose up --build
```

При переходе с ЛР5 зависимости изменились: если frontend-volume `node_modules` уже существует, сначала выполнить `docker compose down -v` именно в каталоге фронтенда, затем пересобрать. Это удаляет его volume зависимостей; Compose бэкенда выполнять с `-v` не нужно.

Открыть тот же порт 3000. Контейнер обращается к API и S3 на хосте через `host.docker.internal`; Linux host-gateway настроен в Compose. `VITE_MINIO_PUBLIC_URL` должен совпадать с origin в ответе бэкенда, обычно это `http://localhost:9000`, даже если upstream прокси использует другой адрес. Docker Compose фронтенда не запускает бэкенд. Остановка: `docker compose down`.

## Страницы и действия

| Страница | Поля и данные | Действия |
|---|---|---|
| Плитка `/corpora` | Порог количества слов 0–200000, изображения, названия, объём, лайки; по 6 карточек | Применить фильтр; Назад/Далее; открыть ленту; удалить свой корпус |
| Лента `/corpora/feed`, `/corpora/:id` | Вертикальное видео, название, описание, количество слов, процент предлогов, лайки | Ещё/свернуть; следующий корпус; поставить/снять лайк после входа |
| Добавление `/corpora/add` | Название, изображение, видео; затем описание и два числовых поля | Создать черновик; продолжить существующий; опубликовать; удалить черновик |
| Вход `/login` | Логин и пароль | Войти; ошибка остаётся на форме |

Нижнее меню содержит **Лента, Добавить, Плитка, Вход/Выход**. Добавление недоступно гостю; прямая ссылка переводит на вход. После входа логин виден в верхней панели. Корзина/заявки из старой методички не реализуются: в текущей теме создаётся и публикуется сам корпус.

**Плитка.** Положение ползунка хранится в Redux и сохраняется при переходах, даже если фильтр ещё не применён; запрос выполняется после «Применить фильтр». Новый фильтр сбрасывает страницу. `query` и `page` передаются серверу и синхронизируются с URL, например `/corpora?query=50000&page=1`. Возврат из ленты сохраняет фильтр. Некорректные параметры нормализуются; страница за пределами каталога возвращается к последней. Успешный пустой ответ остаётся пустым. Удаление доступно только при `is_owner === 1`; затем каталог обновляется.

**Лента.** Сервер возвращает один корпус; следующая запись запрашивается с `id` и `next=true`. Нет предположения, что следующий ID равен `id + 1`. Лайк отправляет `like: 1` или `like: 0`, отображает серверный счётчик и не меняет его при ошибке. Неизвестный ID показывает «Корпус не найден». Статус корпуса из БД не выводится.

**Добавление.** Сначала `GET /corpora/draft`: 404 означает отсутствие черновика. Создание — multipart `name`, необязательные `image` и `video`. Название непустое, до 150 символов. Форматы: JPEG/PNG/GIF/WebP и вертикальные MP4/WebM; содержимое файла проверяет бэкенд. Выбранное изображение сразу показывается в предпросмотре до отправки. Без файлов работают локальные заглушки. Второй шаг отправляет только `description`, `word_count` (целое 0–2147483647), `prep_percent` (0–100) в публикацию. При уже существующем черновике используется он; конфликт создания 409 повторно получает черновик. После публикации открывается лента. Локальные незапубликованные поля не сохраняются между F5.

Для запросов показывается spinner, блокируются кнопки и навигация мышью/клавиатурой. Ошибки позволяют повторить действие. Авторизованный пользователь при отказе сервера видит ошибку, а не mock.

## Redux, Axios и JWT

- `src/store/authorSlice.ts`: логин, токен текущего интерфейса, флаг авторизации, загрузка, ошибка, номер сессии.
- `src/store/corporaSlice.ts`: выбранный и применённый пороги, страница, каталог, лента, источники API/mock, ошибки и активные запросы.
- `src/store/corpusDraftSlice.ts`: свой черновик, поля публикации, результат проверки наличия черновика, запросы и ошибка.
- `src/store/index.ts`: `configureStore` со стандартным middleware, включая thunk, и Redux DevTools. `Provider` подключён в `main.tsx`, hooks типизированы.
- Корпуса загружаются/изменяются через предметные `createAsyncThunk` и сгенерированные методы `corpusApi.corpora.*`. `pending`, `fulfilled`, `rejected` обрабатываются slices.
- Вход/выход — **рукописный Axios** в `src/store/auth.ts`, вызываемый обработчиками компонентов; Redux меняется обычными actions, без auth-thunk и без вызовов сгенерированных методов авторизации.

JWT сохраняется в **localStorage → `attributor.access_token`**. Redux не персистируется и не восстанавливается из localStorage: **F5 возвращает гостевой интерфейс, но JWT остаётся**. Гостевые запросы не получают Authorization даже при сохранённом токене. Его можно скопировать в Postman и проверить персональные признаки. Для возврата пользовательского интерфейса нужен новый вход.

Выход вызывает серверный blacklist через `POST /api/users/logout`. После успеха или 401 удаляет токен, сбрасывает фильтры и пользовательские данные и открывает `/corpora`. При сетевой ошибке сессия сохраняется для повторного выхода. Ответ 401 от защищённой операции также сбрасывает интерфейс. Отложенные ответы прошлой сессии не восстанавливают данные прежнего пользователя.

Гостевой fallback разрешён при сетевой ошибке/таймауте и HTTP 500/502/503/504; запрещён для HTTP 4xx, отменённых запросов и ошибок программы. `src/modules/mock.ts` сохраняет восемь демонстрационных корпусов с локальными медиа. Пустые или недоступные URL используют `public/media/puskin.png` и `puskin.mp4` (720×1280).

## Кодогенерация

```bash
npm run generate-api
```

Генерирует `src/api/generated/Api.ts` из сохранённого `src/api/swagger.json`; запущенный сервер не нужен. Не редактировать сгенерированный файл вручную. Для явного обновления контракта:

```bash
SWAGGER_URL=http://localhost:8080/swagger/doc.json npm run generate-api
```

Генератор использует `httpClientType: 'axios'` и operationId Go Swagger: `getCorpora`, `getCorpusFeed`, `getCorpusDraft`, `createCorpus`, `publishCorpus`, `deleteCorpus`, `setCorpusLike`. Сгенерированные auth-методы существуют как часть полного контракта, но приложение их не вызывает. Необязательные поля Go Swagger приводятся к обязательному UI-типу `Corpus` на границе API.

## Проверки и сдача

```bash
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

На Linux при отсутствии библиотек Chromium установить `npx playwright install-deps chromium`. Playwright сам запускает Vite; для production-проверки предварительно запустить preview. Тесты не снимают скриншоты. Обычные E2E используют перехват API и проверяют клиент без инфраструктуры. Отдельный `tests/real.spec.ts` включается только при `LAB6_REAL_API=1`: требует выделенную тестовую БД и настоящий бэкенд, регистрирует автора, загружает медиа, публикует, ставит лайк, проверяет подписанный S3 proxy и blacklist.

Материалы для самостоятельной сдачи — локальные `docs/lab6/screenshots.md`, `rpz-todo.md`, `control-questions.md`, `verification.md`. `docs/` по существующим правилам исключён из Git. РПЗ, UML-файлы и скриншоты не создавались. Бэкенд — отдельный репозиторий; его файлы не изменялись.
